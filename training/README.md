# Own-voice training

Local single-speaker VITS trainer with fine-tuning as the primary workflow and explicit scratch training as a fallback. The egui application controls setup, preparation, training, stop/resume, preview, ONNX export and numerical verification.

```sh
python3.12 training/setup.py
cargo build -p local-tts-cli
.venv/bin/python training/launch.py --dataset /path/to/dataset.json --output checkpoints/my-voice --init-checkpoint /path/to/trusted-base/latest.pt --steps 10000 --batch-size 2 --device cpu
.venv/bin/python training/export_and_verify.py --checkpoint checkpoints/my-voice/latest.pt --output checkpoints/my-voice/voice
```

Use a trusted project-format VITS `.pt` base in the same language. Initialization
loads the generator/discriminator weights, retains the complete base symbol
inventory (even symbols absent in the new recordings), and starts target step zero
with fresh optimizers/RNG and a default 5e-5 learning rate. The base is not modified.
New symbols or language/frontend/sample-rate/architecture mismatches fail. `--tiny`
engineering checkpoints require the same flag when adapting. The pinned public LJSpeech generator can now be acquired and imported with
`.venv/bin/python scripts/prepare_english_base.py`, or Studio's import button.
It preserves all generator weights and its stochastic duration predictor, uses
the shared native CMU IPA frontend, and starts a fresh discriminator because the
source contains none. See [public base contract and provenance limits](../docs/PUBLIC_BASE.md).
The mirror declares Apache-2.0, but the originating weight-license record remains
a commercial audit gap. Installed ONNX voices are not fine-tuning inputs.

Use `--resume` to continue an existing run; do not also pass `--init-checkpoint`.
Resume restores target weights, optimizer, RNG, learning rate and steps. Base
initialization metadata survives resume and is exported as hashed
`training-origin.json`, including base SHA-256, source revision and recording
rights/earlier lineage. These records do not establish legal clearance of a base.
`--learning-rate` overrides the fresh-run default; resume must retain its saved
rate. Scratch training must explicitly use `--from-scratch` (default rate 2e-4).

`--steps` specifies its total target. Training data must have one speaker, mono 22050 Hz WAV, train/validation splits, clips of 8192 samples to twenty seconds, and documented rights. Prepared tokens and audio hashes are generated by Rust. Scratch training uses `grapheme-v2`: NFC/lowercase/whitespace normalization and explicit RU/UK stress annotations. Export records the frontend version; fine-tuning retains the base frontend, including legacy `grapheme-v1` normalization. Only the pinned public importers read external weights, using restricted deserialization. Training/export still expect trusted project checkpoints.

Source modules are vendored from MIT-licensed VITS, revision `2e561ba58618d021b5b8323d3765880f7e0ecfdb`. Relative embedding indexing is modified to support dynamic ONNX input lengths. Monotonic alignment is a local portable NumPy implementation; it favors correctness over speed.

Validated on macOS ARM CPU using synthetic tones: automated tiny-model scratch training/fine-tuning/resume/stop/export tests and a full-size one-step training/export/synthesis run through the GUI. This verifies mechanics, not speech quality. Sustained own-voice training, CUDA performance and Russian/Ukrainian speech quality still require evaluation on real datasets. Kokoro weights are used only for the pretrained English inference backend, not this trainer.

Read-only checkpoint/dataset inspection is available through
`training/preflight.py` and Studio's compatibility button. `training/compare.py`
exports and verifies base/target checkpoints and generates native held-out audio
with bound lineage/dataset hashes. Studio offers reference/before/after playback,
checkpoint selection and independent copies of evaluated checkpoints. See
[evaluation tools and limits](../docs/EVALUATION.md). Project checkpoint loads now
use restricted `weights_only=True`; no unsafe pickle fallback is used.

The original Ukrainian Piper medium checkpoint is now a second public import
profile: `scripts/prepare_ukrainian_base.py`, or Studio's Ukrainian import/select
buttons. It retains all generator/discriminator tensors and the selected source
conditioning row, then adapts a single new target speaker with fresh optimizers.
Preparation/inference share versioned NFD/BOS/pad/EOS tokens and stress/number
preprocessing. See [Ukrainian base contract, verification and source limits](../docs/PUBLIC_UK_BASE.md).
The Russian Vosk training weights use a different architecture; a separate importer
is still required. Neither downloaded ONNX package is an input to this trainer.

The original Russian Vosk generator is supported as `vosk-ru-multi-v1` through
`scripts/prepare_russian_base.py` and Studio's Russian import/select controls.
Its 62 native dictionary phone indices, fixed source conditioning, mel posterior,
transformer flows and multiband iSTFT vocoder are preserved. Adaptation uses fresh
waveform/duration discriminators and subband spectral losses; resume saves both
optimizers. Corrected ONNX overlap normalization matches the PyTorch training
waveform, while the publisher's unnormalized ONNX conversion is tested separately.
Dictionary/data/consent lineage remains unresolved. See
[Russian base](../docs/PUBLIC_RU_BASE.md).

German/Spanish public CSS10 candidates have pinned acquisition and restricted
inspection tools in `scripts/download_css10_candidates.py` and
`training/inspect_css10.py`. Inspection is read-only and does not create a project
checkpoint. Use `scripts/prepare_css10_base.py de` or `es`, or Studio's new
German/Spanish buttons, to acquire and convert a base. `css10-de-es-v1` preserves
all 696 tensors and speaker/language conditioning; the shared Rust frontend uses
source blank ID 3. Original-network parity and synthetic adaptation/resume/export
checks are provided. See [German/Spanish bases](../docs/PUBLIC_DE_ES_BASES.md).

For French, Italian, Portuguese, Polish and Dutch, use
`scripts/prepare_european_base.py fr|it|pt|pl|nl` (one code per invocation),
or the Studio import/select buttons. The `neon-european-v1` profile preserves
all source weights and the language-specific 129/140 token inventory.
See [European training bases](../docs/EUROPEAN_TRAINING_BASES.md).
